# Execute Task

Prepare to execute on task $ARGUMENTS from `docs/PROJECT_PLAN.md`

## Process

1. **Review `PROJECT_PLAN.md`** to understand the goals, approach, acceptance criteria, and user-verifiable functionality for task $ARGUMENTS
2. **Refer to `REQUIREMENTS.md`** for a primer on the relevant requirements and their acceptance criteria
3. **Refer to relevant technical documentation** in the `docs/` folder for more context on the approach
4. **Review relevant code modules** to understand relevant details of the existing implementation
5. **Remember core implementation guidelines**: KISS, YAGNI, do not create any new documentation unprompted (get explicit user approval first)
5. **Ultrathink** to synthesize the above information into a concrete implementation plan. If you feel the task should be further broken down into subtasks, make that recommendation and provide rationale.
6. **Identify and questions, gaps, risks, or concerns** that need clarification or may hinder our ability to complete the task effectively and with high quality as defined in the current plan and technical documentation
7. **Assess your confidence** in your ability to produce a correct, complete, high-quality implementation. Score your confidence on a scale from 0-100. Remember, confidence is not a measure of the complexity - we can have high confidence despite high complexity if we have a solid plan, good risk mitigations, and sufficient test coverage.
7. **Summarize** your assessment concisely for the user
8. **Interactively iterate** as needed to align on the approach prior to starting to make any code changes
